The current plan validator rejects `status`, `closed_at`, and `close_reason`; the evidence provenance validator also reconstructs the exact expected update argv. `create` imports C into a disposable store, captures B0, applies planned updates or one planned create there, captures B1, derives candidate bytes by splicing planned values plus Beads' changed `updated_at` into C, imports the candidate into a second disposable store, and validates a round trip. It creates an immutable, no-clobber evidence bundle. `promote` revalidates the bundle digest, all snapshots, plan, command provenance, and candidate; checks the current canonical bytes against C; takes the sibling `.beads-reconcile.lock`; rechecks source identity/bytes; and atomically replaces the tracked JSONL. All writers must cooperate with the lock or be quiescent. A post-rename directory-sync error reports that replacement already occurred; no rollback is claimed.

Neither `create` nor `promote` writes the configured live embedded Dolt database or restores Dolt history. The tracked JSONL is an issue/dependency interchange export, not a full database backup. A promoted export showing `closed` is not proof that a live Beads store was closed.

## Beads close behavior and provenance

Repository `CONTRIBUTING.md` documents `bd close <id> "Evidence and outcome"`. The pinned Beads 1.3.1 binary in this environment was checked by SHA-256 against the repository pin. In a disposable synthetic store only, `bd close syn-1 --reason "Synthetic probe close reason"` produced `status=closed`, a UTC RFC3339 `closed_at`, matching `close_reason`, and `updated_at` at the close event; export retained these fields. A separate synthetic import/export confirmed that importing an already-closed record without `closed_at` synthesizes a value from `updated_at` rather than recording an actual close. This derived timestamp is never acceptable as closure evidence. The actual issue row is currently open and has no `closed_at`/`close_reason`; the future isolated test must explicitly verify those B0 facts before invoking close, then verify that the one recorded `bd close` command caused the B1 transition.

The reconciler already records the exact Beads executable path/digest/version, each command argv, working directory, environment digest, exit code, and stdout/stderr digests in its bundle manifest, and verifies the binary remains unchanged around calls. A close extension must retain and strengthen those checks. Pass the approved reason through an argv element (`--reason=<text>`); do not interpolate it through a shell. Do not use `--force`, `--continue`, or automatic next-issue options. If Beads refuses because of a pin, blocker, child, or other guard, abort without force.
