## Implementation plan

**Goal:** close demonstrated test and input-contract gaps that can undermine financial-statement/invoice repair evidence or PDF/UA-2 classification, while keeping the existing remediation/generation boundaries, explicit `ua2` validation, human semantic review, and assistive-technology review distinct.

**Architecture:** focused Go-first, test-first slices. Work only in isolated disposable worktrees based on the then-current protected `origin/main`; keep the parent checkout clean. Keep tests in their owning module because root `./...` does not visit nested Go modules. Do not mutate Beads until the issue workflow (`bd prime`, `bd ready`, `bd show`) is intentionally invoked in a separate authorized step. No product feature scope is implied.

**Priority semantics:** task labels represent defect severity; they do not define execution order. Schedule Task 2 first because it protects PDF/UA evidence classification for the first financial-statement and invoice remediation work. Its severity remains P2: the nested adapter tests catch the removed summary gate, and the review found no current production bypass.
