# Build-machine tools: NeuroStrata and NeuroPlasticity

**Status: Proposed; not installed or enabled.** This applies to build-machine tooling only. It does not add either tool to the product runtime or approved product architecture.

## Scope and setup proposal

If approved, keep the versioned binaries outside the Git checkout at `/workspace/.codex-tools/{neurostrata/1.9.0,neuroplasticity/2.1.0}`. Give both tools a dedicated home under `/workspace/.neurotools-home` so their databases and model caches stay local to this workspace rather than using a shared account home. Keep the versioned binaries and all runtime data out of Git.

For NeuroStrata, use only a local `dap-build` memory namespace for explicitly approved engineering notes. Keep Beads authoritative for work items. Do not import `.beads/issues.jsonl`, ingest the repository or other directories, install hooks, start the daemon, enable SynapticMesh/team Git synchronization, or configure hosted embedding/deduplication providers. The upstream CLI has explicit `task import`, `hooks install`, `daemon`, and `synaptic-mesh` surfaces; do not invoke them. The upstream source warns that directory ingestion embeds source symbols; it is excluded from this proposal.

For NeuroPlasticity, limit any later first run to a disposable copy or worktree and synthetic fixtures. Put its target rules and failed-fingerprint cache in that disposable copy. The cache stores captured stdout and stderr, so it may contain source snippets or fixture content. The optimizer writes the target rules file on the host; do not point it at `AGENTS.md`, project instructions, or other live repository files. Mount the project read-only and use a separate scratch directory. Do not use automatic prompt rewrites or inject generated rules into normal Codex work.

The upstream project has no Codex template at these versions. Codex CLI 0.159.2 is already available as `/opt/codex/bin/codex`; its local help supports `codex exec` with `--sandbox read-only`, `--cd`, and `--skip-git-repo-check`. A NeuroPlasticity run would still need a supported way to make Codex available and authenticated inside the container. Its guide suggests mounting host credentials read-only, but that would expose authentication material to the container; this proposal does not authorize or configure such a mount. Do not create or copy credentials. Resolve a safer approved auth path before attempting an agent run.

NeuroPlasticity v2.1.0 has no standalone evaluator-only mode: it launches `agent_command` in a container before evaluating. A harmless no-op agent in a disposable run can avoid Codex credentials while a container evaluator checks pre-produced results or runs Go checks. The existing Go suite passed CI on the reviewed `main` commit `33865789fa470a692c2d972857f5b3a3f554bed0`. The `host_bash` evaluator allowlist is only `git`, `jq`, `cat`, `ls`, `grep`, and `echo`, so Go checks need a container evaluator. A passing run does not invoke the optimizer, but a failing run stores stdout/stderr and proceeds to it; the default embedded provider downloads Qwen weights if absent. This makes an all-passing first-stage evaluation feasible without Qwen or Codex credentials, but there is no fail-capable evaluator-only mode without separately approving an optimizer-off mechanism or another model path. Keep any run in a disposable copy, because the failure cache can retain output and the optimizer writes its target rules file on the host.

## Build-machine prerequisites observed

Observed in this saved workspace on 2026-10-12: Linux x86_64, Docker client/server 28.4.0, cgroup v2, 5 CPUs, about 17.6 GiB reported Docker memory, and about 30 GiB free on `/workspace`. Docker info reports the built-in seccomp profile and cgroup namespace; a rootless engine was not confirmed. The Codex CLI is 0.159.2. `rustc` and `cargo` are absent, so prefer the fixed release binaries over a source build. No container was launched and no model was fetched during this inspection.

The two executable assets total about 43.5 MiB. First use may also fetch the roughly 523 MB Nomic ONNX model, ONNX Runtime support binaries, and the 2.5 GB Qwen GGUF, depending on which tools are run. The machine has room for these downloads, but only about 17.6 GiB memory and 5 CPUs; local Qwen inference is likely CPU-bound. Container image pulls, just-in-time package installation, Hugging Face model downloads, and hosted evaluators require network access. NeuroPlasticity's egress plan is an application policy, not a network firewall.

HEAD-only probes of `https://github.com/Cognilogical/NeuroStrata/releases/download/v1.9.0/neurostrata-mcp-linux-amd64.tar.gz` and `https://github.com/Cognilogical/NeuroPlasticity/releases/download/v2.1.0/neuroplasticity-linux-x86_64` returned HTTP 200, redirected to `release-assets.githubusercontent.com`, and reported the expected asset lengths. No release bytes were fetched; GET and checksum verification remain untested. The earlier `api.github.com` request was denied by the proxy, but that does not block the tested release-asset route. HEAD probes of `https://huggingface.co/nomic-ai/nomic-embed-text-v1.5/resolve/main/onnx/model.onnx` and `https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF/resolve/main/Qwen3-4B-Instruct-2507-Q4_K_M.gguf` failed before an HTTP response with `Tunnel connection failed: 403 Forbidden` for `huggingface.co`. This points to the environment's outbound proxy/domain policy, not a Hugging Face API authorization error. Model downloads require an approved network-policy change allowing `huggingface.co` and any storage/CDN host to which its resolve URLs redirect; the redirect host was not tested because the initial connection was denied. No proxy or allowlist configuration was changed. For the tested release downloads, no network-policy change appears necessary, but the actual transfer remains unverified.

## Proposed reproducible sequence and approval gates

1. Recheck the release tags, asset digests, model file revision/digest, and dependency license inventory.
2. After approval, obtain only the two listed Linux x86_64 assets through the tested GitHub release-asset route; verify their SHA-256 values before extraction under `/workspace/.codex-tools/`.
3. Before running NeuroStrata, separately approve the ONNX Runtime/model downloads. Use the dedicated tool home and local namespace only; do not ingest repository files, sample PDFs, private reports, Beads data, or credentials.
4. Before running NeuroPlasticity, separately approve its embedded Qwen model download (about 2.5 GB) or select an already-present, approved local model without reading secret-bearing paths. Prepare a disposable copy and synthetic fixture; do not run against live repo instructions or fixtures.
5. Resolve the containerized Codex auth blocker without creating credentials or mounting existing auth files. If no safe supported auth route is available, keep NeuroPlasticity limited to local deterministic evaluators and do not claim it evaluated Codex behavior.
6. Only after these gates, test version output, isolated namespace behavior, and the selected evaluator in the disposable environment. Keep all generated databases, caches, rules, and captured logs local and untracked.

No binaries, model weights, container images, services, Codex MCP entries, hooks, Beads imports, or product dependencies were added in this preparation step.
