## Scope and setup proposal

If approved, keep the versioned binaries outside the Git checkout at `/workspace/.codex-tools/{neurostrata/1.9.0,neuroplasticity/2.1.0}`. Give both tools a dedicated home under `/workspace/.neurotools-home` so their databases and model caches stay local to this workspace rather than using a shared account home. Keep the versioned binaries and all runtime data out of Git.

For NeuroStrata, use only a local `dap-build` memory namespace for explicitly approved engineering notes. Keep Beads authoritative for work items. Do not import `.beads/issues.jsonl`, ingest the repository or other directories, install hooks, start the daemon, enable SynapticMesh/team Git synchronization, or configure hosted embedding/deduplication providers. The upstream CLI has explicit `task import`, `hooks install`, `daemon`, and `synaptic-mesh` surfaces; do not invoke them. The upstream source warns that directory ingestion embeds source symbols; it is excluded from this proposal.

For NeuroPlasticity, limit any later first run to a disposable copy or worktree and synthetic fixtures. Put its target rules and failed-fingerprint cache in that disposable copy. The cache stores captured stdout and stderr, so it may contain source snippets or fixture content. The optimizer writes the target rules file on the host; do not point it at `AGENTS.md`, project instructions, or other live repository files. Mount the project read-only and use a separate scratch directory. Do not use automatic prompt rewrites or inject generated rules into normal Codex work.

The upstream project has no Codex template at these versions. Codex CLI 0.159.2 is already available as `/opt/codex/bin/codex`; its local help supports `codex exec` with `--sandbox read-only`, `--cd`, and `--skip-git-repo-check`. A NeuroPlasticity run would still need a supported way to make Codex available and authenticated inside the container. Its guide suggests mounting host credentials read-only, but that would expose authentication material to the container; this proposal does not authorize or configure such a mount. Do not create or copy credentials. Resolve a safer approved auth path before attempting an agent run.

NeuroPlasticity v2.1.0 has no standalone evaluator-only mode: it launches `agent_command` in a container before evaluating. A harmless no-op agent in a disposable run can avoid Codex credentials while a container evaluator checks pre-produced results or runs Go checks. The existing Go suite passed CI on the reviewed `main` commit `33865789fa470a692c2d972857f5b3a3f554bed0`. The `host_bash` evaluator allowlist is only `git`, `jq`, `cat`, `ls`, `grep`, and `echo`, so Go checks need a container evaluator. A passing run does not invoke the optimizer, but a failing run stores stdout/stderr and proceeds to it; the default embedded provider downloads Qwen weights if absent. This makes an all-passing first-stage evaluation feasible without Qwen or Codex credentials, but there is no fail-capable evaluator-only mode without separately approving an optimizer-off mechanism or another model path. Keep any run in a disposable copy, because the failure cache can retain output and the optimizer writes its target rules file on the host.
