The Go fixture reader accepts regular files only, reads at most the configured cap plus one byte, rejects oversize, hashes the captured byte slice against the expected digest, and parses/repairs from that same captured input bytes. The repair test re-reads the fixed source afterward and rejects a change from the bytes used. This provides the bounded same-byte-slice contract for the Go repair path. A regression covers pre-cancelled input, non-regular input rejection, and a capped regular-file read. The 30-second context describes cooperative pdfcpu processing and direct subprocesses; it is not a hard filesystem deadline and does not guarantee interruption of a blocked `os.Open` or in-flight filesystem read. Beads `dap-jo9.1.6.5` tracks that filesystem latency boundary. The distinct `dap-jo9.1.6.6` follow-up applies to the shell CI validator's separate stat/hash/install/rehash pathname operations, not this Go reader.
