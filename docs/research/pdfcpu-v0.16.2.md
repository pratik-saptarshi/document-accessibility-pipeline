Source tag `v0.16.2` resolves to commit `b41a41d5323f6119ff6a183ad3f287eb4a20a617`; the release `go.mod` requires Go 1.26.0 or later. The release license is Apache-2.0. ## Bounded full-write characterization

The repository harness is `internal/pdfpreserve/roundtrip_test.go`. It creates synthetic, one-page fixtures for statements, invoices, correspondence, and reports; each contains marked content, a deliberately non-monotonic MCID sequence, a sparse ParentTree with a null slot, `/P` parent references, an MCR with `/Pg`, an MCR with `/Pg` and `/Stm`, a link annotation/OBJR, a text widget/OBJR with a field value, a base font, page geometry, and title metadata. It performs `api.ReadContextFile` → `api.WriteContextFile` with the ordinary full-write path → fresh `ReadContextFile`.

Observed on all four fixtures: page count, media box/page dictionary, page content and form-XObject decoded streams, font dictionary, link and widget dictionaries, structure dictionaries, ParentTree entries and null hole, document title, and Poppler's rendered pixels, text, tag-tree view, and link target are unchanged. The form field value remains `42.00`. In this tiny fixture, rendered PNG hashes match exactly at 72 DPI. The writer changes the Producer and adds creation/modification timestamps; the title is retained. These are characterization results for the fixture only, not a general fidelity threshold.

The fixture covers sparse/non-monotonic MCIDs, `/P`, `/Pg`, `/Stm`, annotation/widget OBJR, and a null ParentTree slot. It does not establish correctness for multiple pages, arbitrary third-party structure trees, signatures, embedded files, OCR, complex fonts, tagged forms/appearance streams, or all annotations. The small form widget has no appearance stream. Visual comparison was run with the workspace Poppler `pdftoppm` at 72 DPI; the committed Go test does not require Poppler, so image/text/tag-view comparisons are recorded here as a workspace run, not as CI assertions.

## Two-page inherited-attribute characterization

`TestFullWriteRoundTripPreservesTwoPageInheritedAttributes` adds a second inline-generated synthetic PDF 1.7 input. Its source SHA-256 is `4a39c3f22b9c0f682c9b2816003d9167b24db7481b122e4c8fe6a0285dd5320d`; the test pins this digest and confirms the source file remains unchanged after writing to a separate candidate path. The fixture is authored in `internal/pdfpreserve/roundtrip_test.go`; it uses no external or customer documents. Both `/Page` dictionaries inherit `/MediaBox [0 0 612 792]` and `/Resources` containing `/F1` Helvetica from their `/Pages` parent. Each page has a distinct content stream and `/StructParents` key. The synthetic `/StructTreeRoot`, `/ParentTree`, paragraph structure elements, and MCR `/Pg` references associate each page with its own MCID 0.

With pdfcpu v0.16.2's ordinary full-write API, the Go characterization verifies both pages' effective media boxes and inherited font resources, dereferences `/F1` in each context and compares its font dictionary, decoded page content, page-to-MCR references, `/StructParents`, and ParentTree entries before and after the write. The expected text markers are present on their respective pages. Negative controls mutate the inherited page-tree media-box height from 792 to 600 and the indirect font object's `/BaseFont` from `/Helvetica` to `/Courier`; the comparisons reject both geometry and font mutations. This directly links to [TC-REM-FIDELITY-001](../validation/cases.md#tc-rem-fidelity-001).

Observed metadata changes: the source `/Producer` value `DAP synthetic fixture generator` becomes `pdfcpu v0.16.2`; the writer adds `/CreationDate` and `/ModDate`; `/Title` is retained. The characterization does not compare the complete serialized files byte-for-byte and does not use an independent renderer for this new fixture. It does not exercise inherited rotations/crop boxes, deeper page trees, multiple tagged content items per page, forms, annotations, fonts beyond the synthetic Helvetica reference, third-party PDFs, signatures, embedded content, or semantic correctness. It is preservation evidence for this exact synthetic case only—not a runtime dependency approval, engine selection, repair implementation, PDF/UA validation, or conformance claim.

The test follows each source leaf's parent chain and checks the nearest ancestor resource dictionary is the nested node's dictionary. Source nesting is verified; output page-tree topology is unconstrained because this characterization targets effective inherited attributes. Synthetic negative controls mutate the nested CropBox and Rotate independently; the comparisons reject both changes. This extends the two-page inherited-resource case and directly links to [TC-REM-FIDELITY-001](../validation/cases.md#tc-rem-fidelity-001).

This case does not include tags, nonempty resource entries, fonts, forms, annotations, or an independent renderer; the drawn content streams are compared structurally, not visually. It does not test arbitrary page-tree depth, invalid rotations, CropBox clipping, third-party files, signatures, embedded content, or semantic correctness. It is bounded synthetic preservation evidence only, not PDF/UA validation, conformance, a repair implementation, or production-engine approval.

## AcroForm widget appearance characterization

`TestWidgetAppearanceFullWritePreservesAppearance` adds a separate synthetic PDF 1.7 text widget with an indirect `/AP /N` Form XObject. The fixture SHA-256 is `fe63ce6d66dfdcb5cf8870c31809fe0ad86382bf590485aacdafd7e0701f73d5`. Its trailer points `/Info` to object 17, the metadata dictionary; the focused `TestWidgetAppearanceFixtureReferencesInfoDictionary` regression asserts that link and the fixture title so it cannot accidentally point at appearance stream object 19. The widget `/V` and visible appearance both contain `42.00`. The AcroForm `/DA` has its own `/DR /Font /F1` binding to Type1 Helvetica object 7, and the appearance Form XObject has independent `/Resources /Font /F1` bound to Helvetica object 18; the appearance also has `/BBox [0 0 100 20]` and identity `/Matrix`. The test validates the Catalog-to-StructTreeRoot link, page tree/count, AcroForm default and appearance font resources, field/page annotation links, AP/N stream dictionary and raw/decoded content, widget OBJR plus ParentTree bindings, title, page content, and effective geometry. It does two independent ordinary full writes to separate candidate files, freshly reads both outputs, and checks the input hash is unchanged. It does not require serialized output byte identity.

Red/green negative controls changed only appearance text while preserving the widget `/V`, changed the appearance BBox, changed the referenced appearance font, removed the Catalog `/StructTreeRoot` binding, and removed the AcroForm `/DR`. The text test checks that the input stream's raw bytes contain `42.00`, decodes them before changing content, and asserts that the reread negative has exactly the `99.00` appearance program while `/V` remains `42.00`; it updates stream length metadata so the PDF remains readable. Each mutation is rejected for its expected reason. The earlier generic comparator did not cover this new appearance object, and source-structure assertions initially dereferenced the root without checking that the Catalog linked it; the focused controls exposed both gaps.

An available workspace Poppler `pdftoppm` 26.05.0 rendered the full-write candidate at 72 DPI. The positive output visibly showed `42.00`; a separately full-written negative with appearance text `99.00` (widget `/V` still `42.00`) visibly showed `99.00`. PNG SHA-256 values were `3a5ce221d5bede8e44f04fe4008e3380aff54a24b239b164592d45242c18d1d9` (positive) and `8d4c88a19bcc8c6ae10f4c1af301d6519f421b1ea57cd84786a51599ed7b1cf5` (appearance-text negative). Poppler emitted a Fontconfig cache permission warning in this read-only environment; renders completed. This is one synthetic widget and one renderer, not a general visual-fidelity result. It does not cover appearance states, rollover/down appearances, button/check-box widgets, field hierarchies, clipping/rotation variants, nonstandard fonts, third-party PDFs, semantic agreement between `/V` and `/AP`, or assistive-technology behavior. Visual fidelity for those cases remains unknown.

### Checkbox normal-appearance state characterization

`TestCheckboxAppearanceFullWritePreservesAppearanceStates` covers checked and unchecked synthetic PDF 1.7 checkboxes (`/FT /Btn`). The checked fixture SHA-256 is `76e0f268c1d324d3dd1769dc4103d3de67278898df6967548cc59e9ad9cfdb95`; its `/V` and `/AS` are both `/Yes`. The unchecked fixture SHA-256 is `0fd54351dc5ebcaf6f236ccf62fd67400656d3bb52987f29bf1b9bac774f8f1c`; its `/V` and `/AS` are both `/Off`. Both use an `/AP /N` dictionary mapping `/Off` and `/Yes` to distinct indirect Form XObjects. Each state has an explicit empty local `/Resources` dictionary, a 20-by-20 `/BBox`, identity `/Matrix`, and vector-only stream content (a square for `/Off`; a square and checkmark for `/Yes`). For each fixture, the test checks the trailer `/Info` reference and title, Catalog-to-page-tree and Catalog-to-`/StructTreeRoot` links, AcroForm-to-widget and page-annotation bindings, page geometry/content/resources, widget `/P` and `/StructParent`, `/V`-to-`/AS` agreement, each named state reference and decoded stream, the widget OBJR, and ParentTree bindings. It performs two separate ordinary full writes per fixture (four writes total), freshly reads and checks each output, and verifies that each original input hash is unchanged.

`TestCheckboxAppearanceComparatorRejectsStateMutations` begins each control from a validated source fixture, writes the targeted mutation, rereads the output, verifies the exact reread mutation, and checks the expected comparator diagnostic. Controls swap the two still-valid Form references in the `/AP /N` state dictionary, bind `/V /Yes` to `/AS /Off` while both named states remain available, and alter only the decoded `/Yes` vector stream while retaining `/V` and `/AS` as `/Yes`. The stream-content mutation decodes before editing and updates stream length metadata. The red case against the prior text-widget-only path failed because that oracle expected the text-widget fixture's distinct `/Info` title; the new checkbox-specific comparator passed the positive case and rejects each negative for its intended checkbox-state or stream-content reason.

Poppler `pdftoppm` 26.05.0 rendered the full-write checked `/Yes` candidate at 72 DPI; the inspected image showed the synthetic label and checked vector box (PNG SHA-256 `ea0d2ccb80e1a87e324ea700bbf05eba25acbcf46405a69114087793ab2c83f9`). Fontconfig reported that its cache directories were not writable, but rendering completed. This workspace render is not a CI assertion and covers only the selected `/Yes` state in one renderer; the unchecked `/Off` state is exercised by full-write and decoded-stream checks but was not separately rendered. No semantic review or assistive-technology session was performed. These tests and the render do not establish PDF/UA conformance, accessible labeling, correct meaning, or usability with assistive technology; rollover/down states, third-party form variants, and general visual fidelity remain open.

## Source-reviewed behavior and limits

At the pinned release, the normal full writer serializes the catalog `StructTreeRoot`, `AcroForm`, page annotations, and `StructParents`. Reduced-feature modes remove `StructTreeRoot`; therefore, the static-review risk is mode-specific. `WriteIncrement` is an incremental-writing primitive, not a complete semantic remediation API. A candidate adapter must choose the ordinary full-write path explicitly and test its mode settings. Source evidence: [`write.go` at v0.16.2](https://github.com/pdfcpu/pdfcpu/blob/v0.16.2/pkg/pdfcpu/write.go).

## Dependency evidence and remaining gate

The library itself is Apache-2.0 and is Go-first. Its release `go.mod` lists direct and indirect modules, including Cobra, YAML, x/crypto, x/image, x/text, TIFF, and Unicode helpers. This Phase 0 harness pins pdfcpu exactly at v0.16.2; it does not make the library an approved runtime dependency. Before any production adoption, record and review the full resolved transitive license inventory, security posture, supported versions, and compatibility with the approved input profile. The initial Go proxy fetch returned 403 in this environment; the module was subsequently downloaded from the exact official VCS tag, and `go.sum` records its checksums. The checked-in module dependency uses the tagged version and standard Go checksum verification.

## Proposed next test boundary

Keep remediation and generation adapters replaceable. Before choosing this writer, extend characterization to multi-page tagged examples, page-tree inheritance, form appearances, annotation variants, font embedding/subsets, XMP/Info metadata policy, signatures, and failure/unsupported behavior. A successful parse or round-trip is not a semantic repair result, PDF/UA validation, WCAG conformance, or accessibility release approval.
