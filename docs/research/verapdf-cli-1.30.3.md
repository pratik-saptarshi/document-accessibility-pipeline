## Real PDF/UA-2 integration evidence

The CLI is invoked with `--flavour ua2 --format xml`; no automatic detection or fallback profile is allowed. In the exact 1.30.3 output, the selected profile is named `PDF/UA-2 + Tagged PDF validation profile`; both the existing adapter and new Go-only report verifier pin that exact report value and fail closed for any other profile. The actual CLI returns exit code 0 for a compliant report and 1 for a noncompliant finding.

Two unchanged CC BY 4.0 oracle controls come from the official [`veraPDF/veraPDF-corpus`](https://github.com/veraPDF/veraPDF-corpus) repository at commit `bb75f4f0073d9350dfd058c0162a367e6fadf25e`. Their provenance and SHA-256 values are recorded in [`internal/pdfua/testdata/README.md`](../../internal/pdfua/testdata/README.md): `8.2.4-t01-pass-a.pdf` (pass) and `8.2.4-t01-fail-a.pdf` (finding), both testing ISO 14289-2 clause 8.2.4. Running the authenticated CLI produced:

- Pass control: exit 0, profile `PDF/UA-2 + Tagged PDF validation profile`, `isCompliant="true"`, 0 failed rules/checks. Candidate SHA-256: `c255fc1a6d4aeeef41d2b6ee7009dec43754e01dcd3d2c697e662f0040bef96b`; report SHA-256 from the captured run: `fa2741342fa94a3ceb227ed39b56300764cdc598e32c4548d0ae8695f63efe0d`.
- Finding control: exit 1, the same profile, `isCompliant="false"`, 1 failed rule/check for a nonstandard structure element. Candidate SHA-256: `2d0996fa1c49decc6efa1241461832d7724062b14244d24663684f58d28badd0`; report SHA-256 from the captured run: `43e596657b51a7c163edd148c7c70c3bdb58179273131e24cef51f1f92eaebc0`.
- Each control emits a schema-version-1 JSON contract and raw XML report. The Go-only verifier checks the pinned validator and base-image identity, final image ID syntax, named oracle and PDF digest, report SHA-256, explicit profile, and exit/report agreement. Unknown/duplicate metadata, malformed XML, modified report bytes, invalid candidate/tool hashes, unsupported exits, and oversized data fail closed. The CI artifact contains only these reports and contracts, retained for one day; no PDF, JAR, or image is uploaded.
- Synthetic Docker-shim tests verify the enforced container flags, candidate mutation rejection before process start, output flood bounds, operational exit handling, and forced container cleanup. A second Docker build with appended bytes in a copied CLI JAR failed the in-image pinned hash check. The existing Go adapter API and synthetic process/report tests remain; its real-JAR test source stays opt-in and is not run in the Go job.

These controls are machine-validator oracles. A machine pass cannot establish that document meaning, reading order, or assistive-technology behavior is correct. Human semantic and assistive-technology review remain separate release gates.
