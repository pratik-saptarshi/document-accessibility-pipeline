## Fit with this repository

This repository already has the parts of the workflow that fit: Beads is the canonical work tracker, [`AGENTS.md`](../../AGENTS.md) requires reading decisions and prior evidence, the existing `dap-` skills cover test-first changes, review, and verification, and the guarded publisher and protected CI govern publication. The compatible addition is a bounded-work rule: handle one authorized work item at a time; for an explicitly autonomous or repeated run, stop after six task iterations, or after three unsuccessful attempts on the same item, preserve the partial state, and report the blocker. These limits trigger escalation; they do not waive acceptance criteria or close work.

After verification, record a short result and reusable finding in the canonical Beads issue or relevant project document. Keep it sanitized and linked to evidence. Do not add a second Markdown backlog, send repository or Beads content to an external memory service, or install the reference's 29-skill library. This repository's existing skills have their own provenance and review record; use those rather than duplicate upstream packages.

The reference's runtime architecture does not fit the current approved environment. Its scheduler, NeuroStrata database, custom MCP client, connector gateway, Google Drive backup, and egress configuration would add persistent services, data movement, or network policy. None is authorized here. The upstream `AGENTS.md` also specifies the reference repository's commit identity and branch naming; those are not adopted as instructions or credentials for this project. The accepted permanent Neuro model and authentication blocker remains in force; this note does not reopen it. Keep Go as the primary implementation language, Beads as the work tracker, and Java/veraPDF in the isolated CI job.

## Historical reliability and security limits at `2c7b0dbe`

The historical pin was not a ready-to-install package. It had no license file, automated tests, CI workflow, or general installer in that reviewed tree. Its runbook downloads the Nomic model through a mutable `resolve/main` URL even though it separately names a model commit. Its Beads example saves the archive under `beads.tar.gz` but checks the checksum list using the release asset filenames, so the documented checksum command may not refer to the saved archive. Do not execute that runbook.

The historical source at this pin had operational-documentation drift. The README and watchdog's top-of-file comments said it revived a dead daemon, and the runbook suggested restarting directly or waiting for the watchdog; the executable logic treated a down daemon as the expected idle state. PR #5 intended to stop a healthy daemon after an idle interval, keep timestamped daemon logs, and archive logs with database backups. There was an exception on its unchanged-database path: that branch called `stop_daemon` before the function was defined later in the script, so Bash reached an undefined command and, with `set -euo pipefail`, exited before stopping the daemon or logging the intended completion. This is based on static inspection; the upstream script was not executed. PR #3 fixed the earlier stop race by signalling every matching PID; the old first-PID stop behavior must not be attributed to the current stop logic at that pin. On the changed-database path, a failed 30-second stop was logged and caused the backup to be skipped, while that path's caller exited successfully. The watchdog was tied to that VM's paths and Drive destination, and the reviewed source had no tested restore procedure or remote-retention proof. These are review findings about the pinned files, not claims that this repository has those services or failure modes.
