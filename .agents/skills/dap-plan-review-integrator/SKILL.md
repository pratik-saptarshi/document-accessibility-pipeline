# Review-to-plan integration

Read the complete review, target plan, relevant accepted decisions, and
repository constraints. Extract each distinct finding with its evidence and
severity, then map it to the plan as already addressed, a gap, a correction, a
new concern, or pre-existing. Independently validate recommendations against
domain facts. Preserve disagreements and uncertain claims instead of silently
accepting or discarding them.

Edit only the plan and supporting files the user authorized. Do not update
global memory, create peripheral records, or change unrelated plans by default.
Apply actionable edits narrowly, re-read for consistency, and produce a concise
traceability table mapping each finding to its disposition and edit/evidence.
Use Beads only under the repository's issue workflow; valid deferred findings
need a product-reviewed rationale and testable acceptance criteria.

If there are no actionable findings, report that the plan remains unchanged.
Do not implement the plan, publish, or merge unless separately requested.
