# Receiving code review

Treat feedback as a hypothesis to evaluate, not an instruction to obey or
dismiss. Read the full comment and current code at its cited revision; reproduce
or independently verify its concern when practical. For each finding, record a
verified fix, a reasoned product disposition, or evidence why it does not apply.
Fix critical and acceptance-blocking issues. Handle lower-priority valid items
using the repository's Beads and review rules. Re-read the final diff and check
that the response addresses the finding and exact current revision.

Do not paste private reasoning. Keep replies factual, concise, and supported by
evidence. A resolved label alone does not establish that the concern is fixed.
Repository approval, CI, publication, and merge gates remain in force.
